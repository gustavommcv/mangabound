# Mangabound v0.1.0-alpha.11

Mangabound is a desktop app that turns manga you already have — folders of chapters or `.cbz` files — into books ready for your e-reader.

**This is an alpha.** There is no auto-update yet, and the installers are not code-signed. See "Known limitations" before installing.

## Read this before updating

- **Every conversion is different from v0.1.0-alpha.10's.** The bundled converter, mangapress, goes from 0.6.0 to 0.7.2, which makes pages the way Kindle Comic Converter 12 does. The visible fix: **in KOReader, the pages of an EPUB no longer come out 11 to 15% wider than they were drawn.** If a book you made with an earlier version looked stretched, convert it again. A book made now will not match one made before page for page.
- **Linux: the packages of v0.1.0-alpha.10 could not convert books for a normal user.** The folder with the bundled tools was installed readable by root only, so the tools could not be run by a normal account. This release fixes it, and the build now fails if a Linux package holds anything a normal user cannot read. If you installed alpha.10 from a package, install this one over it.
- **Windows: your unsaved books move.** The books you have converted and not saved, and the covers you attached, were kept in `%LOCALAPPDATA%\Mangabound`, which is the folder the installer puts the app in, and the uninstaller removes that folder, so uninstalling very likely took them with it (not tried on a real install). They now live in `%LOCALAPPDATA%\Mangabound Data`. The first start of this version moves them there by itself, never replacing anything that is already there. Nothing needs to be done, but if you have books you care about that are not saved, save them first.
- **Sharing now serves every book that is ready to save.** Before, sharing one conversion served only that conversion, so a book converted afterwards never reached the reader, and nothing said why. Now the ready books of every pending conversion are shared together, newest first, and one converted while sharing is running shows up on the reader. That includes conversions from days ago that you never saved or deleted. While they are shared, a pending conversion cannot be deleted: stop sharing first.

## What's new since v0.1.0-alpha.10

### Books and options

- **The options have grown with mangapress 0.7.** Page layout is five short sections (Reading, Double-page spreads, Size and borders, Cropping, Two-page view), image options are two (Color and tone, Page images), and there is a Cover section. **Use the images as they are** turns off everything that would change a page, and says so on each control it locks. Color now follows the device you choose (the colour readers keep colour, the others make grayscale), until you change it by hand.
- **A cover of your own for each book.** The details page has a Covers card that lists every book the item makes: choose an image for one, or add the images of a folder in name order. A cover you chose by hand is never replaced by a folder.
- **A Kobo's EPUB is named `.kepub.epub`**, as Kindle Comic Converter names it, with **Name the book .epub** to turn that off. A loose CBZ, or a folder converted without grouping, takes its cover from a `Covers` folder beside it when there is one.
- **The results say what mangapress noticed.** When a book was made but something about it is worth knowing (pages smaller than the screen, pages that look converted already, files that were not images), the results say so once for each kind, with the books it is in, in the app's words.
- **The language of a book.** The details page offers **Use pt-br** when the folder names declare a language, and a language tag is always written the way BCP 47 recommends (`pt-br` becomes `pt-BR`), so that a reader that compares tags exactly can match them to a dictionary or a hyphenation rule.

### What the app tells you about your chapters

- **Two copies of one chapter.** A folder with the same chapter from two groups makes mangabind leave **all** the copies out of the book. The editor now refuses to place one of them and says to remove all but one from the folder, and the results say when a book lacks chapters (copies, chapters missing inside a volume, chapters with no pages).
- **Folders whose names are not chapter names** (`Omake`, `Ch.004 [GroupA]`) used to be left out without a word. The queue and the editor now name them, for a folder and for each title of a library.
- **A link in a manga folder is followed only when it leads to a file inside that folder** (mangabind 0.6.1). A folder from someone else could carry a link to a private file of yours and have it copied into a book that you then save or share. Such a link is left out and the results say so. If you keep your library as links on purpose, put a copy of the file in the folder.
- **Converting some titles of a library binds only those.** Converting the one title that failed, from a library of fifty, used to bind the other forty-nine first and throw the result away.

### Saving and keeping your files

- **Saving to a FAT or exFAT drive** (a Kindle or a Kobo over USB, an SD card) needed room for the book twice; it needs it once.
- **Saving your volumes no longer drops what else is in `mangabind.json`** (a source, notes of your own, keys of other tools). A `mangabind.json` that is not valid JSON is refused instead of overwritten.
- **The validated plan names the books the run will really make** (your title, the format's extension), not the CBZ names of the joining step. Names that differ only in how an accent is written are no longer taken for different, so one cannot replace the other.
- **A title that is too long for a file name** (more than 200 bytes) is refused at the start instead of failing after the whole conversion, and a typo that would ruin a book (a gamma of `18` for `1.8` made an almost black one) is refused. One bad value in the saved options no longer throws away all the others.
- **What a run that was killed left behind is cleared** at the next start: a half-made first book in the pending folder, and the scratch copies of its volumes in the temporary folder.

### Sharing and safety

- **Stopping sharing ends the downloads in progress**, a reader that goes to sleep halfway through a book is let go after a minute, and quitting no longer waits for a stalled download.
- **The catalog answers only to an address of your computer**: the numbers the app shows, `localhost`, or the computer's own name. A web page you visit cannot reach a share with no password through your browser. If your router gives the computer a name and your reader uses it, use the address shown in the app.
- **The window is held more tightly.** The app's page is served from the app's own address instead of `file://`, can talk only to the app, and is given only the permissions the app uses (camera, microphone, location and notifications are refused). Sharing starts only on a network address the app listed.
- **One copy of the app runs at a time.** A second launch brings the first forward, instead of sharing its settings and unsaved books.
- A malformed address on the share is not found, instead of an error, and a title with a character XML does not allow no longer makes the reader refuse the whole catalog.

### Using the app

- Number fields take what you type when you clear one and type another (`1` and then `2` is `2`, not `12`), a decimal comma is taken as a point, and a number the app will not take is put back.
- Cancel stops the item that is running, also when it is pressed as the next one starts, and what a job reports at the very start is no longer dropped.
- A question that opens in place (deleting pending books, resetting options) takes the keyboard focus, so it is read out and its buttons are next.
- The window does not show a screen about an item that is gone, and what you chose before the saved options had loaded is not undone.
- A screen reader is told less often while a conversion runs: a message for each tenth of the work, not for each page.
- A book over a gigabyte is shown as "1.5 GB".

Behind the scenes the app's decisions were pulled out of their handlers and put under tests that must cover every line, and the release procedure now refuses to publish a commit that is not on `main` or whose checks did not pass. There is nothing to do about either.

## Installing

**Windows:** download `Mangabound-0.1.0-alpha.11.Setup.exe` and run it. The installer is not code-signed, so Windows may identify it as coming from an unrecognized publisher. If you prefer not to run an installer, download the portable `.zip`, unzip it, and run `mangabound.exe` directly.

**macOS (Apple Silicon):** download the `.zip`, unzip it, and drag `Mangabound.app` to your Applications folder. The app is not signed or notarized, so macOS may block its first launch.

**Debian, Ubuntu, and derivatives:** download the `.deb` and install it with your usual tool, for example:

```text
sudo apt install ./mangabound_0.1.0.alpha.11_amd64.deb
```

**Fedora, RHEL, and derivatives:** download the `.rpm` and install it with your usual tool, for example:

```text
sudo dnf install ./mangabound-0.1.0.alpha.11-1.x86_64.rpm
```

**Arch, and derivatives:** download the `.pkg.tar.zst` and install it with pacman, for example:

```text
sudo pacman -U ./mangabound-0.1.0_alpha.11-1-x86_64.pkg.tar.zst
```

This is a direct download built by this project's CI, not a submission to the AUR. Pacman resolves the app's runtime dependencies from your usual repositories.

## Security prompts

The Windows installer is not code-signed, and the macOS app is not signed or notarized. Both operating systems may show a security warning; do not disable either operating system's protection globally.

These notes were written before the published files of this release were downloaded and opened by hand, so the exact prompts are not documented yet; this section is updated after that check. What the project's CI does for every change: the installers are built on Windows, macOS and Linux, the packaged app is run on all three systems, including under Wayland, and the build fails if a Linux package holds a folder or a file that a normal user cannot read.

## What's bundled

Mangabound includes two pinned command-line tools; nothing is downloaded after installation:

- **[mangabind](https://github.com/gustavommcv/mangabind) v0.6.1** — groups chapters into volumes, can bind the whole series into one `.cbz` for conversion, reports how many pages it has copied, and does not follow a link that leads outside the folder.
- **[mangapress](https://github.com/gustavommcv/mangapress) v0.7.2** — converts for your e-reader the way Kindle Comic Converter 12 does and builds the nested EPUB table of contents.

Both are checksum-verified at build time, and again every time the app starts.

## Known limitations

- Combining the whole series into one book supports EPUB only, not CBZ or PDF.
- The author is written into EPUB and PDF books only; a CBZ carries no author.
- Pending books are local to this app installation and are not a permanent backup. Keep exported files in a safe location. Once a completed run has been closed and cleaned up, or explicitly deleted, deleted exports require reprocessing.
- Sharing the ready books shares all of them, including old conversions you have not saved or deleted.
- A link in a manga folder, or in a shared folder, that leads outside that folder is not followed.
- The app is in English only.
- No automatic updates; download and install each new release manually.
- No code signing or notarization on any platform, and no build attestation is published with the files yet.
- macOS builds support Apple Silicon only, not Intel Macs.
- No AppImage in this alpha.
- The Arch package is a direct download; there is no AUR submission yet.
